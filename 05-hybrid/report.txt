1. IMPLEMENTATION

Decomposition:
The partition() function divides the grid horizontally among MPI ranks.
Rank r receives N/P + (r < N%P) rows, where P is the number of ranks.
Remaining rows go to the first ranks to balance the workload. Each rank
allocates two local grids (current and next) with two extra halo rows.
Configurations with more ranks than rows are rejected.

Example: N = 10, P = 3 (numbers represent global row indices).

Rank   Top halo   Owned rows    Bottom halo
0      zero       [0 1 2 3]     4
1      3          [4 5 6]       7
2      6          [7 8 9]       zero

counts = {4, 3, 3}
starts = {0, 4, 7}

Initialization:
Each rank initializes its own cells with the supplied initial_cell()
function using global coordinates (first + i, col). OpenMP parallelizes
initialization, and the initial grid remains identical to the reference.

Communication:
Before each generation, exchange_halos() uses two MPI_Sendrecv() calls
to exchange boundary rows with neighbouring ranks. MPI_PROC_NULL is used
for missing neighbours, so the external halo rows remain zero.

Synchronization:
The evolve() function parallelizes the outer row loop with OpenMP and
static scheduling. The archived implementation uses firstprivate for
pointers and scalar parameters, while the underlying grids remain shared.
An alternative using shared was also tested. Double buffering separates
reads from writes, and the implicit barrier ensures all threads finish
before the buffers are swapped. MPI_THREAD_FUNNELED is used because only
the initializing thread of each rank calls MPI functions.

Population counting:
OpenMP reduction combines thread-local counts. MPI_Reduce with MPI_SUM
combines the local totals on rank 0, which prints the global population.

Final-image export:
The export_grid() function uses MPI_Gatherv() to collect owned cells,
excluding halos, on rank 0. Variable counts and displacements support
uneven partitions. The supplied save_pbm() function writes the image.


2. VALIDATION

The hybrid implementation was compared against the provided sequential
reference using both standard output and the final PBM image. The 15
recorded tests cover grid sizes from 1 to 2048, different step counts,
MPI ranks and OpenMP thread counts.

The tests include minimal grids, zero generations, uneven partitions,
one owned row per MPI rank and larger grids. These cases exercise
initialization, boundary handling, halo exchange, local computation,
population reductions and the final gather.

All 15 recorded configurations matched both outputs. Population counts
check the total number of living cells at each step, while the final-grid
comparison also checks their exact positions. For zero steps, the output
is the initial grid and no population lines are printed.

The archive documents this build; versions for the other runs are not
independently recorded.

MPI implementation, rank/thread counts and placement:
Archived build: Open MPI 5.0.11. The tested layouts use 1, 2, 4 or 8 MPI
ranks and 1, 2 or 4 threads per rank. Both shared and firstprivate were
tested on both machines. Explicit rank binding and thread placement
were not recorded.

Fixed N and step count:
N = 4096, steps = 200.

Timing method and precision:
Three runs per configuration. Median wall-clock time reported to 0.01 s.
The exact timing command was not recorded.

Scope:
Whole-program wall time, including computation, communication, output
and MPI startup/exit.

Resource count used for parallel efficiency:
Requested workers = MPI ranks * OpenMP threads per rank.
Speedup = serial median time / parallel median time.
Efficiency (%) = 100 * speedup / requested workers.

Each series uses its own sequential baseline. Medians, speedup and
efficiency are calculated from the recorded run times, with speedup
rounded to two decimals and efficiency to the nearest integer percent.
Efficiency is calculated before rounding speedup.

4. SHORT DISCUSSION

Scaling:
The hybrid implementation with one rank and one thread is slower than
the sequential reference in all four experiments, consistent with MPI
and OpenMP overhead without useful application-level parallelism.
Increasing the worker count reduces runtime up to the best tested
configuration: 4 MPI ranks and 2 OpenMP threads per rank on both machines
and with both clauses. Speedup is sublinear due to factors such as
communication, synchronization, memory bandwidth and runtime overhead.

Layouts with the same number of workers perform differently. With
firstprivate on the MacBook Pro, 4 ranks x 2 threads took 1.66 s,
2 ranks x 4 threads took 1.86 s, and 8 ranks x 1 thread took 2.79 s.
More MPI ranks create more partition boundaries, whereas OpenMP threads
share a local grid. The measured differences suggest a benefit from
balancing the two parallelization levels, although these timings do not
isolate individual overheads.

Comparison of shared and firstprivate:
The firstprivate version was faster in all eight parallel layouts on
the MacBook Air and seven of eight on the MacBook Pro. For the best
layout, the Air improved from 2.96 to 2.20 s (25.7% less time), and
the Pro improved from 1.97 to 1.66 s (15.7% less time).
On the Pro, 8 ranks x 1 thread instead changed from 2.77 to 2.79 s,
a small increase that may reflect normal timing variability.

The firstprivate clause copies pointer values and scalar parameters
rather than the grids themselves. This may allow different compiler
optimizations, but the timing results alone cannot establish the cause
of the improvement. The sequential baselines also varied between runs.

Hardware comparison:
The MacBook Pro was faster in all shared layouts and seven of eight
firstprivate parallel layouts. For the best layout, the Air/Pro time
ratio was 1.50 with shared and 1.33 with firstprivate. The Pro has more
performance cores (10 compared with 4), which may contribute to the
observed difference. The actual core placement was not recorded.

Limitations:
All experiments were performed on one node, so multi-node scalability
was not evaluated. Only one problem size and three runs per configuration
were used for performance testing. Rank binding and thread affinity
were not recorded, and whole-program timing includes file output and
MPI startup/exit, preventing separate analysis of computation and
communication costs.

Overall, the best measured result was obtained on the MacBook Pro with
firstprivate, 4 MPI ranks and 2 threads per rank: 1.66 s, speedup 3.54
and efficiency 44%.
